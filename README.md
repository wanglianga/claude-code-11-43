# 校园供餐多源数据质量与过敏原暴露覆盖分析工具

一款纯浏览器端（React 18 + TypeScript + Vite）的数据分析工具，帮助数据分析师判断五类来源数据——
**供应商成分、菜谱、厨房实际用料、餐次日志、学生饮食限制**——能否可靠关联，并量化过敏原暴露分析中
**多少记录有证据支持、多少存在候选待确认、多少因来源缺失无法判定**。

- 不调用任何真实学校服务，不上传个人数据；所有数据保存在浏览器本地 IndexedDB。
- 读取随项目提供的 CSV / JSON 样例（`public/sample-data/`，全部为虚构数据）。
- 未匹配记录一律计入「未知」，**不会被当成「没有过敏原」**；厨房 `PLANNED`（计划使用）不参与实际暴露计算。

## 一、核心设计

### 1. 三桶证据口径（每条领餐记录恰好落入一桶）

| 桶 | 含义 | 进入条件 |
| --- | --- | --- |
| 有证据支持的匹配 `CONFIRMED` | 链接链完整、原料解析有证据 | 供应商**精确编码**、**已批准别名**或分析师**人工确认**，且餐次/用料/限制链路完整 |
| 存在候选但需确认 `CANDIDATE_PENDING` | 有名称/规格/单位/成分候选，但未确认 | 候选**确认前不进入正式统计**，不低报暴露 |
| 来源缺失无法判定 `UNKNOWN_MISSING` | 来源缺失或链接断裂 | 区分空餐次、关联不存在、时间无法归属、批次未到齐、限制为空/未生效等具体原因 |

精确匹配与上下文候选**并行**：只有精确编码/批准别名自动生效；候选经分析师确认后才复用该决定。

### 2. 字段四态（不折叠成同一个失败数）

- `FIELD_NOT_PROVIDED` 源文件未提供该字段（如乙校供应商文件没有 `cert_no` 列）
- `VALUE_EMPTY` 字段值为空（甲校部分行 `cert_no` 留空）
- `REF_NOT_FOUND` 关联对象不存在（领餐→餐次、餐次→菜谱、限制学生→领餐）
- `BATCH_PENDING` 来源批次尚未到齐（`kit-b-2`，预期 6 行）

### 3. 不可变运行与版本固定

每次分析运行固定引用：**全部输入文件 SHA-256、映射版本+修订号、规则版本（rules-v1）**。
补发旧数据或修改映射后生成的是**新运行**，历史运行不被静默改写；「运行对比」页展示三桶迁移矩阵、
覆盖率变化与质量问题增减。

### 4. 映射乐观锁（多标签页）

保存映射时重新读取 IndexedDB 校验修订号；另一标签页已提交更高版本时，后提交者保存被拒绝并提示重载，
已确认映射不会被覆盖（同时通过 `BroadcastChannel` 主动推送版本变化）。

## 二、目录结构

```
public/sample-data/          随项目提供的样例输入（CSV/JSON + manifest + 种子映射）
  manifest.json              批次清单（含晚到批次 sup-a-2、未到齐批次 kit-b-2）
  standard_ingredients.json  10 种标准原料及其过敏原
  seed_mappings.json         初始映射（批准别名 + 人工确认决定）
  schoolA/ schoolB/ meal/ diet/
src/
  lib/        CSV 解析、SHA-256、IndexedDB 封装、数据加载、导出、批次统计
  engine/     规则、上下文索引、质量检查、匹配引擎、运行引擎与对比/预览（纯函数，可单测）
  state/      React 全局状态、IDB 持久化、乐观锁
  components/ 共享组件（徽标、抽屉、覆盖图）
  pages/      总览 / 来源批次 / 映射工作台 / 质量检查 / 分析运行 / 运行详情 / 运行对比
Dockerfile + docker-compose.yml + nginx.conf   一键静态部署
```

## 三、本地启动

### 方式 A：Node 开发服务器（推荐用于本地开发）

要求 Node.js 22（容器内固定入口 `/opt/node-22/bin/node`）。

```bash
npm install --registry=https://registry.npmmirror.com
npm run dev        # http://localhost:5173
```

生产构建与本地预览：

```bash
npm run build      # 类型检查 tsc -b + vite build，产物在 dist/
npm run preview    # http://localhost:4173 静态预览（含 SPA 回退）
```

> 必须通过 HTTP 服务访问（需要 `fetch` 读取样例数据），不要直接双击打开 index.html。

### 方式 B：Docker / Compose 一键启动

```bash
docker compose up --build
# 打开 http://localhost:8080
```

多阶段构建：node:22-alpine 构建静态资源 → nginx:1.27-alpine 托管（已配置 SPA 路由回退）。
停止：`docker compose down`。

## 四、测试账号与隐私说明

本工具**没有登录体系、没有后端、没有测试账号密码**：

- 样例学生均为匿名学号（`S-1001` … `S-1023`、`S-9999`），由校医维护的饮食限制按匿名学号生效。
- 所有映射、人工确认、分析快照与运行结果仅写入浏览器 IndexedDB（库名 `campus-meal-dq`）。
- 「分析运行」页提供「重置工作区」，可清空本地数据并恢复随项目提供的种子映射。
- 可在浏览器 DevTools → Application → IndexedDB 中核查全部本地数据，不存在任何网络上报。

## 五、验证方式（建议操作路径）

1. **总览页**：查看 11 个来源批次的输入/有效/重复/关联/未知行数与三桶覆盖环形图；点开「指标详情」查看分子、分母、排除条件、来源范围。
2. **来源批次页**：打开 `sup-b-1` 看到 `cert_no` 为「源文件未提供」；打开 `sup-a-1` 看到 3 行「字段值为空」；打开 `kit-b-2` 看到「批次尚未到齐」；可逐行下钻原始行。
3. **质量检查页**：核对重复键、缺失键、单位冲突、时间无法归属、多对多连接五类问题并下钻原始行。
4. **映射工作台**：在「菜谱/厨房简称」中找到待确认候选「芝麻」（影响餐次 MS-A-0901-D / 领餐 SV-006），
   点「预览影响」→ 看到候选 1→0、确认 4→5、未知 19 不变 → 「保存并生成新运行」。
5. **分析运行 → 运行详情**：三桶筛选、逐层下钻（计算轨迹、参与计算的厨房实际用料原始行与映射决定、领餐原始行），
   导出 JSON（含运行编号、口径摘要、未知范围与免责声明）或 CSV。
6. **运行对比**：选择两个运行，查看桶位迁移矩阵与覆盖率变化；旧运行保持不变。
7. **多标签页冲突**：再开一个浏览器标签页，在两个标签页同时编辑映射，后保存者收到版本冲突横幅且保存被拒绝。

## 六、样例实际计算结果（本仓库已执行验证）

基于当前样例与种子映射（`npm test` 中以断言固化）：

- 领餐记录 **24 条 = 有证据 4 + 候选待确认 1 + 来源缺失未知 19**；4 条已确认记录全部命中真实暴露
  （SV-004 乳、SV-008 蛋、SV-009 麸质、SV-010 乳），确认安全 0 条。
- 质量问题计数：重复键 **4**、缺失键/关联缺失 **4**、单位冲突 **1**（高筋粉 kg/L）、
  时间无法归属 **2**（非法 supper 窗口、lunch 时间越界）、多对多连接 **1**（条码 `6901001000017` 编码复用，
  晚到批次中同条码变成含芝麻的新配方，系统拒绝自动合并并降级为待确认候选）。
- 确认「芝麻」候选后：候选 1→0、确认 4→5、未知保持 19；`diffRuns` 输出迁移矩阵
  `CANDIDATE_PENDING → CONFIRMED = 1`，变化记录仅 SV-006。
- PLANNED 行（K-A-11）不进入任何领餐的实际用料证据；9/8 餐次因 `kit-b-2` 未到齐计入未知而非零暴露。

## 八、口径与防误读声明

导出文件内置免责声明：**「未知/无法判定」表示当前来源缺少证据，不等于该餐确认不含过敏原；
接收方不得据此作出『无过敏原』结论。** 导出 JSON 同时携带运行编号、规则/映射版本、全部输入文件哈希、
口径摘要、完整未知范围与每条领餐的评估明细。
